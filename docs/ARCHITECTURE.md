# 설계와 근거

> 공식 문서 확인일: 2026-10-09. 제한·요금은 바뀔 수 있으니 배포 전에 아래 링크를 다시 확인하세요.

## 1. 구성

```
휴대폰(React) ── HTTPS POST /api/answer ──▶ Worker ──RPC──▶ EventDO (행사 1개 = Object 1개)
      ▲  └──── WebSocket /ws?role=p ────────▶ Worker ──fetch─▶   ├─ SQLite: participants / rounds / answers / results / meta
      │                                                         ├─ WebSocket Hibernation (태그 p / b / h)
전광판(React) ── WebSocket /ws?role=b ──────▶ Worker ───────────▶ └─ Alarm(자동 마감)
진행자(React) ── POST /api/host/cmd, WebSocket /ws?role=h ──────▶
정적 화면·이미지 ── Workers Static Assets (Worker 를 거치지 않음)
```

| 구성 요소 | 역할 |
|---|---|
| `worker/index.ts` | 쿠키 세션 서명 검증, Origin·CSRF 검사, 참가 코드 HMAC 해시·AES 암호화, 라우팅. **무상태 CPU 작업을 여기서 처리**해 여러 인스턴스로 분산하고, DO 에는 검증된 참가자 ID 만 넘긴다. |
| `worker/event-do.ts` | 행사 상태 머신, 답안 접수·마감·채점·재채점, 실시간 방송, 결과 내보내기. |
| `worker/quiz/bank.ts` | 문제·정답(서버 전용). `src/` 에서 import 하지 않는다. |
| `src/` | 참가자(`/`), 진행자(`/host`), 전광판(`/board`) 한 개의 SPA. |

## 3. 왜 이렇게 했나

### 행사 하나 = Durable Object 하나 (먼저 단순하게)
마감·중복 방지·집계는 **한 곳에서 순서대로** 처리될 때 가장 쉽게 정확해진다. DO 는 한 번에 하나의 이벤트만 실행하므로,
`await` 가 없는 동기 코드 구간은 다른 요청이 끼어들 수 없는 원자적 단계가 된다. 접수 경로(`submit`)와 마감(`closeRound`)은
모두 `await` 가 없는 동기 코드이고, SQLite 호출(`sql.exec`)도 동기다. 이것만으로 500명이 충분하다고 가정하지 않았고,
로컬 부하 시험으로 DO 처리 시간을 따로 쟀다([TESTING.md](TESTING.md)). 클라우드 측정은 아직 하지 않았다.

### 답안은 HTTPS, 진행 상태는 WebSocket
- 답안은 "저장됐다"는 확인이 꼭 필요하다. HTTP 요청-응답은 응답 = 확인이고, 실패하면 같은 `reqId`·`seq` 로 안전하게 재시도할 수 있다.
  이동통신에서 WebSocket 이 반쯤 끊긴 상태(보낸 것 같지만 도착하지 않음)를 판별하기 어려운 문제도 피한다.
- WebSocket 은 서버 → 화면 방향의 상태 알림(문제 시작·연장·마감·다음 문제)에만 쓴다. 학생 화면으로는 상태가 바뀔 때만 보내고,
  답안 하나마다 방송하지 않는다. 타이머는 **종료 시각(endsAt)과 서버 시각(now)** 만 보내고 기기가 그린다.

### SQLite 스키마
`worker/event-do.ts` 의 `MIGRATIONS` 참고. 핵심:
- `answers PRIMARY KEY (run, pid)` — 참가자·진행 버전별 유효 답안은 **하나**. 수정은 UPDATE.
- `answers_run_norm` 인덱스 — 마감 후 "많이 낸 답" 집계와 채점(`INSERT … SELECT … json_each`)에 사용.
- `results PRIMARY KEY (run, pid)` — 채점 결과. 재채점은 **지우고 다시 계산**하므로 몇 번 반복해도 중복 반영이 없다.
- `participants.code_hash UNIQUE` — 참가 코드는 HMAC 해시로만 조회. 재내보내기용으로 AES-GCM 암호문을 함께 보관.
- `cmd_log(cmd_id PK)` — 진행자 명령의 재시도를 같은 결과로 응답(멱등).
- `_schema(v)` — 마이그레이션 버전. constructor 에서 한 번만 적용.

### 메모리는 캐시일 뿐
메모리에 두는 것: 현재 상태 사본, 현재 문제 제출 인원 수, 세션 세대 캐시, 빈도 제한 버킷, 진행자 묶음 타이머.
모두 SQLite 에서 다시 만들 수 있거나(상태·제출 인원·세대) 잃어도 안전하다(빈도 제한·타이머).
E2E 시험에서 강제 재시작(`ctx.abort`)과 15초 유휴 후 Hibernation 을 모두 관찰했고, 그 뒤에도 상태·답안·결과·WebSocket 이 복구됐다.

## 4. 접수 판정 시점과 마감 경계 (정의)

- **판정 시점**: 답안 요청을 EventDO 가 처리하기 시작하는 순간의 서버 시각 `now`.
- **접수 조건**: `round.status == 'open'` 이고 `now < round.ends_at`, 그리고 요청의 `run`·`qid` 가 현재 진행 중인 문제와 같을 것.
- 기기에서 마감 전에 눌렀어도 **서버 판정 시점이 종료 시각 이후면 `closed` 로 거부**한다. 클라이언트가 보낸 시각은 쓰지 않는다.
- **자동 마감**: Alarm 이 `ends_at` 에 실행되어 마감한다. Alarm 이 늦게 실행되더라도, 그 사이 도착한 모든 요청·연결·명령은
  먼저 `tick()` 으로 종료 시각을 확인해 마감을 실행한 뒤 처리되므로 늦은 답은 반영되지 않는다.
- **조기 마감**: 진행자 명령 처리 순간 `ends_at = min(ends_at, now)` 로 기록한다.
- **마감과 저장의 경합**: 접수와 마감은 모두 `await` 없는 동기 구간이라 둘 중 하나가 먼저 **완전히** 끝난다.
  먼저 저장된 답은 마감 트랜잭션의 채점에 반드시 포함되고, 마감 뒤 처리된 요청은 거부된다. (E2E "마감과 저장 경합" 시험)
- **저장 완료 후 응답**: DO 의 output gate 가 SQLite 기록이 확정될 때까지 응답을 내보내지 않는다. 따라서 `accepted` 응답은 영구 저장 이후에만 도착한다.
- 연장(`+10초`)은 열려 있을 때만 가능하며, 새 종료 시각을 모든 화면에 보내고 Alarm 을 다시 건다.

## 5. 중복·순서·재시도

| 값 | 누가 정함 | 용도 |
|---|---|---|
| `run` (진행 버전) | 서버. 문제를 시작할 때마다 1씩 증가, 초기화해도 줄지 않음 | 이전 문제·초기화 전 진행의 지연 요청 차단 (`stale`) |
| `qid` | 서버 문제 ID | 다른 문제로 잘못 간 요청 차단 |
| `seq` | 클라이언트. 같은 문제 안에서 제출할 때마다 +1 (localStorage 보관, 재접속 시 서버의 마지막 seq 로 맞춤) | 늦게 도착한 옛 버전이 최신 답을 덮지 못하게 (`superseded`) |
| `reqId` | 클라이언트. 요청마다 무작위 | 같은 요청의 재시도 식별 (`duplicate`) |

서버 규칙: 기존 답의 `req_id` 와 같으면 `duplicate`(이미 저장), `seq ≤ 기존 seq` 면 `superseded`(덮지 않음), 더 크면 UPDATE.
참가자 ID 는 **서명된 쿠키에서만** 가져오고, 본문에 `pid`·`name` 을 넣어도 무시한다.

클라이언트: 네트워크 오류·5xx·429 면 같은 `reqId`·`seq` 로 지수 백오프 재전송. 화면이 마감·다음 문제 상태를 받으면
**미전송 답을 버리고**(다음 문제로 보내지 않음) "마감되어 접수되지 않았습니다"를 표시한다.

## 6. 인증·세션·권한

- 쿠키 3종: `qz_p`(참가자: 행사·참가자·세션 세대), `qz_h`(진행자), `qz_b`(전광판: 행사·키 버전). 모두 `HttpOnly; SameSite=Lax; Path=/`, HTTPS 에서는 `Secure`.
  값은 `base64url(JSON).HMAC-SHA256` 이며 만료 시각을 포함한다(참가자 14시간, 진행자 12시간, 전광판 24시간).
- 비밀값은 `SESSION_SECRET` 하나에서 용도별로 파생(쿠키 서명 / 코드 해시 / 코드 암호화). `HOST_PASSWORD` 와 함께 Wrangler secret 으로만 넣는다.
- **진행자**: 비밀번호 로그인. IP 별 10분간 10회 실패 시 잠금(실패 기록은 `sys:auth` Object 의 SQLite).
- **전광판**: 진행자 화면에서 발급하는 링크(`/board#k=행사코드.무작위키`) 로만 로그인. 키는 해시로만 저장하고, 새로 발급하면 이전 전광판 연결을 끊는다.
  `#` 뒤 값은 서버 로그·Referer 에 남지 않으며, 페이지가 읽은 즉시 주소창에서 지운다. **행사 코드만으로는 진행자·전광판 권한을 얻을 수 없다.**
- **참가 코드**: 8자, 헷갈리는 문자(0 O 1 I L) 제외 31종 → 31⁸ ≈ 8.5×10¹¹(약 39.6비트). 500개를 발급해도 무작위 한 번에 맞힐 확률은 약 5.9×10⁻¹⁰.
  추가로 IP 별 5분간 실패 200회 초과 시 그 IP 의 시도만 잠시 거부한다(통신사 공유 IP 로 정상 참가자 다수가 막히지 않도록 넉넉하게).
  코드는 DB 에 HMAC 해시(행사 코드를 섞음)와 AES-GCM 암호문으로만 저장한다.
- **여러 기기 정책 — 마지막 입장 우선**: 같은 코드로 새 기기에서 입장하면 세션 세대가 올라가고, 이전 기기는 즉시 `kicked` 를 받아 연결이 끊기며 답안도 낼 수 없다.
  답안은 참가자 단위이므로 새 기기에서 기존 접수 답이 보인다. 새로고침은 쿠키가 그대로라 영향이 없다.
- **한계**: 참가 코드는 "코드를 가진 사람"을 확인할 뿐 **실제 1인 1참여를 보장하지 않는다**(코드를 남에게 주거나, 한 사람이 여러 코드를 받는 것을 막을 수 없다).
- **WebSocket**: 업그레이드 요청의 `Origin` 이 같은 출처(또는 `ALLOWED_ORIGINS`)여야 하고, 역할별 쿠키를 검증한 뒤 DO 에 역할·ID 를 헤더로 넘긴다(클라이언트가 보낸 `x-quiz-*` 헤더는 지운다).
- **CSRF**: 모든 POST 는 `Origin` 일치 + `x-quiz: 1` 사용자 정의 헤더 + `application/json` 을 요구한다. 교차 출처에서는 사전 요청(preflight)이 필요해 차단된다.
- 빈도 제한: 참가자별 순간 8회·초당 4회 회복. 답안 30자(정규화 후), 원문 100자, 요청 본문 20KB 제한.
- 사용자 입력은 React 텍스트로만 렌더링(HTML 로 실행하지 않음). CSV 내보내기는 수식 주입(`= + - @` 시작)을 막는다. CSP·X-Frame-Options 등은 `public/_headers`.
- 로그에는 경로와 오류 종류만 남기고 코드·쿠키·비밀번호는 남기지 않는다.
- **개발용 기능**: Object 강제 재시작 명령은 `APP_ENV=local` **그리고** `DEV_MODE=1` 일 때만 동작한다. 배포 환경(`env.test`)의 `APP_ENV` 는 `cloud-test` 라서 `DEV_MODE` 가 실수로 들어가도 동작하지 않는다.

## 8. 하나의 Object 가 병목일 때의 대안 (구현하지 않음)

클라우드 부하 시험에서 DO 왕복 시간(`Server-Timing: do;dur=`)이 크게 늘거나 overloaded 오류가 나오면, 먼저 접수 경로를 더 줄인다
(예: 진행자 묶음 갱신 간격 늘리기, `genOf` 캐시 적중률 확인, 응답 JSON 축소). 그래도 부족하면 **접수용 Object 를 나눈다**.

- **분할 기준**: `shard = hash(pid) mod N` 의 `IntakeDO`(N=4~8). 한 참가자는 항상 같은 샤드로 가므로 `(run, pid)` 유일성은 샤드 안에서 그대로 보장된다.
- **전역 마감**: EventDO 가 유일한 시계 기준이다. 문제 시작 시 `run·qid·endsAt` 을 모든 샤드에 RPC 로 전달하고, 각 샤드는 지금처럼 `now < endsAt` 로 판정한다.
  조기 마감은 "지금"이 아니라 **약간 뒤의 시각 `closeAt = now + 300ms`** 을 정해 모든 샤드에 보낸 뒤, 각 샤드가 `min(endsAt, closeAt)` 으로 판정한다.
  이렇게 하면 RPC 도착 시점 차이와 무관하게 모든 샤드가 같은 경계를 쓴다.
- **최종 집계**: 마감 시각이 지난 뒤 EventDO 가 모든 샤드에서 "마감 확인 + 채점 결과(정답자 ID 목록·상위 답 집계)"를 받아 합친다.
  모든 샤드가 응답하기 전에는 결과 공개 단계로 넘어갈 수 없게 하고, 재채점은 샤드별로 "지우고 다시 계산" 후 다시 합친다(멱등).
- **중복 방지**: `reqId`·`seq` 규칙은 샤드 안에서 동일하게 동작한다. 참가자→샤드 매핑이 바뀌지 않도록 N 은 행사 중에 바꾸지 않는다.
- 비용: 샤드 수만큼 DO 요청이 늘지는 않는다(참가자 요청은 한 샤드로만 감). 마감·집계 시 RPC 가 N 개 추가된다.

검증 없이 처음부터 이 구조로 가지 않았다. 판단 근거는 클라우드 부하 시험의 DO 왕복 시간과 overloaded 건수다.
